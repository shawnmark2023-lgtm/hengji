# 衡记 HENGJI：产品方案 v0.1

> 看见每一笔消费的长期价值。

## 1. 产品定义

衡记不是只把流水换成饼图的记账工具，而是一套本地优先的“消费价值系统”：记录钱花到哪里、买了什么、用了多久、每天/每次实际花了多少、现在还能卖多少钱，并用可解释的规则给出可执行的优化建议。

首发平台：iOS、Android、Windows、macOS。首版不登录、不建立云端身份、不做账户校验；数据默认保存在设备本地。账户、端到端加密同步和正式平台 OAuth 放到上线阶段。

## 2. 核心用户

- 想坚持记账，但无法忍受高录入成本和分类错误的人。
- 有数码、家电、服饰、兴趣装备等耐用品，希望知道“买得值不值”的人。
- 想出售闲置物品，需要掌握当前二手行情和最佳出售时机的人。
- 重视隐私，不愿把完整账单交给不透明云服务的人。
- 需要在手机快速记录、在电脑深度复盘的人。

## 3. 核心价值闭环

1. **低摩擦收集**：手动快速记账、自然语言草稿、CSV/账单文件导入、分享扩展；经批准后接入官方 OAuth。
2. **把流水变成物品**：消费记录可以关联到“产品资产”，保存购买价、维护费、使用次数、保修和价格历史。
3. **计算真实使用价值**：同时展示总拥有成本、日均拥有成本、净日均成本和单次使用成本，避免单一指标误导。
4. **跟踪退出价值**：通过合规二手报价连接器保存样本、来源、时间和置信度，用中位数估计当前残值。
5. **给出可解释建议**：按支出占比、趋势、预算、重复订阅、低使用率和可出售闲置生成建议，并展示触发依据。
6. **行动后复盘**：标记建议为已采纳/忽略，后续比较节省额和使用率变化。

## 4. 功能范围

### 4.1 首版可用产品（MVP）

- 首页：本月支出、环比、可支配额度、分类占比、近期洞察。
- 流水：新增、编辑、删除、搜索、筛选、分类、退款、收入/支出、备注、来源。
- 物品：购买价、购买日期、维护费、使用记录、保修、目标使用周期、当前残值。
- 价值指标：
  - 总拥有成本 = 购买价 + 维护/配件/手续费。
  - 日均拥有成本 = 总拥有成本 / 已拥有天数。
  - 净日均成本 = (总拥有成本 - 当前残值) / 已拥有天数。
  - 单次使用成本 = (总拥有成本 - 当前残值) / 使用次数。
- 二手比价：手工报价、演示行情提供器、供应商适配接口、中位数/区间/置信度；所有演示数据明确标注“示例行情”。
- 智能分析：分类占比、预算燃烧速度、环比异常、商户集中度、疑似订阅、低使用物品、出售候选、建议影响估算。
- 导入中心：CSV/JSON 预览、字段映射、去重、分类建议、逐条确认、撤销导入。
- 隐私中心：本地处理说明、数据导出、全部清除、连接器授权状态。
- 自适应 UI：手机底栏，桌面侧栏；键盘、鼠标、触控和系统深浅色模式。

### 4.2 Beta

- 用户主动选择的 PDF/图片账单 OCR。
- Android 经商店审批后的金融短信导入；不读取非金融短信。
- iOS FinanceKit（仅在地区、账户和 entitlement 允许时）。
- 支付/电商平台官方 OAuth 连接器；平台未提供个人账单读取能力时不伪造能力、不爬虫。
- 价格提醒、保修提醒、订阅到期提醒。
- 可选匿名聚合 AI 文案：仅发送统计摘要，默认关闭，不发送原始流水。

### 4.3 正式上线

- Passkey/Sign in with Apple 等系统级登录，设备绑定和恢复码。
- 端到端加密同步、冲突解决、设备撤销。
- OAuth token 安全托管、授权撤销、审计日志、数据保留策略。
- App Store/Google Play/Windows/macOS 签名、公证、隐私清单和上架材料。

## 5. 导入策略与边界

“不获取个人信息”按可执行定义处理为：不采集姓名、手机号、证件、通讯录、位置、广告标识和设备指纹；不建立跨应用画像。交易和消费记录本身仍是个人/金融相关数据，必须最小化、透明处理。

连接器按可信度分四级：

| 级别 | 方式 | 首版状态 | 原则 |
|---|---|---|---|
| L0 | 手动、CSV/JSON、用户选择文件 | 可用 | 本机解析、可预览、可撤销 |
| L1 | 系统分享扩展、剪贴板确认、OCR | 框架/Beta | 必须由用户主动触发 |
| L2 | 官方 OAuth / FinanceKit | 接口与沙箱 | 仅在平台批准 scope 后启用 |
| L3 | 爬虫、密码代填、逆向私有接口 | 永不支持 | 高风险且不可持续 |

微信支付公开查单/账单能力面向商户自身订单，并非读取任意消费者完整账本；淘宝、京东公开订单接口也以卖家/商家/联盟业务为主。产品文案不得在取得真实能力前声称“一键同步全部平台”。

## 6. 智能分析原则

- **先确定性、后生成式**：金额、比例、趋势、异常和节省估算由可测试算法产生；模型只负责解释，不改写事实。
- **可解释**：每条建议包含依据、影响、置信度和可执行动作。
- **可纠正**：分类、商户归一化、订阅识别均允许用户更正；规则会使用本地纠正结果。
- **不制造焦虑**：不使用羞辱性文案，不把所有娱乐消费视为浪费。
- **非金融建议**：只做支出管理与消费价值建议，不提供投资、借贷或税务结论。

## 7. 体验标准

- 首次启动直接进入带示例数据的本地体验，30 秒内完成第一笔记录。
- 高频新增流水不超过 3 个主要交互步骤。
- 删除、导入、批量修改可撤销；危险操作二次确认。
- 文字、颜色、图表均可被辅助技术理解；不依赖颜色传达唯一含义。
- 移动端触控目标至少 44×44 pt；桌面完整键盘导航、焦点状态和常用快捷键。
- 所有金额使用定点数/最小货币单位，不使用浮点数保存。
- 空状态、加载、失败、离线、权限拒绝和数据冲突都有明确恢复路径。

## 8. 成功指标

- 激活：首次会话完成 1 笔流水或成功导入样例。
- 7 日价值：至少查看 1 次物品成本或采纳 1 条建议。
- 录入效率：手动新增中位时长 ≤ 12 秒；导入后需要手工修正的比例持续下降。
- 信任：导入可撤销率、分类纠正率、连接失败率透明可观测。
- 质量：核心领域逻辑测试覆盖率 ≥ 85%；崩溃自由会话 ≥ 99.8%（上线后）。
- 隐私：首版网络请求为 0（用户主动打开外部链接除外）；无广告 SDK、无行为追踪 SDK。

## 9. 明确不做

- 不伪装成银行或支付平台，不保存第三方密码。
- 不在未获授权时抓取电商/二手平台页面。
- 不把演示价格当作实时行情。
- 不在 MVP 引入社交、广告、贷款导流、投资推荐或复杂复式会计。
- 不用一个超大共享模块掩盖平台差异；系统能力通过明确端口和原生实现接入。
