# 长截图与一键读取账单

日期：2026-08-03（Asia/Shanghai）

范围：Android 实现与 Windows/Android 共享导入流程。iOS/macOS 延期；Windows 当前仍使用手动记账或 CSV/JSON，不宣称具备本机 OCR。

## 1. 用户怎么用

Android 有三个入口：

1. 点底部“记一笔”，选择“识别长截图（可提取多笔）”。
2. 点“记一笔”或进入“设置 → 导入账单”，选择“一键读取图片或 PDF”。
3. 在相册、文件或其他应用里主动把图片/PDF 分享给恒迹。

长截图要求每组记录能找到日期、商户和金额；普通单张账单在缺少日期时会以当天作为待确认日期。识别结果不会直接保存，而是进入“字段对应关系 → 逐条预览/去重 → 最后确认 → 整批撤销”的既有五步流程。

## 2. 数据流与隐私边界

```text
用户主动选择或分享图片/PDF
  → Android 系统文件授权
  → 内置 ML Kit 本机 OCR
  → 保守提取日期/商户/金额/方向/币种/分类候选
  → 只保留结构化候选，丢弃原图引用与 OCR 原文
  → 合成短生命周期 CSV，进入既有导入预览
  → 用户确认后原子写入；可按整个批次撤销
```

- 使用随 APK 静态交付的 `com.google.mlkit:text-recognition-chinese:16.0.1`，运行期没有模型下载器。
- APK 不声明 `INTERNET`、`READ_SMS`、`RECEIVE_SMS` 或相册/媒体库读取权限。
- 不监控剪贴板，不自动截屏，不登录支付平台，不读取 Cookie/密码，不调用私有 API，也不做屏幕抓取或爬虫。
- 原文件、OCR 原文和系统分享 URI 不进入 Compose 状态、账本、分析模型或日志；账本只接收用户最终确认的结构化候选。

## 3. 不可信输入与失败策略

| 边界 | 策略 |
| --- | --- |
| 文件体积 | 最多 20 MiB；内容提供方未报告大小时流式计数，超限或空文件拒绝 |
| 长图尺寸 | 源图最多 100M 像素、单边最多 100,000 像素；超过 8M 像素后按纵向分片，最多 50 片 |
| 解码内存 | 每片输出宽度最多 1,600、高度 2,000；逐片 OCR 后立即回收 Bitmap |
| PDF | 最多 20 页；单页渲染最多 4M 像素 |
| OCR 文本 | 最多 100,000 字符、5,000 个非空行 |
| 账单候选 | 一次最多 200 笔；第 201 笔会导致整次识别明确拒绝，不静默截断 |
| 金额 | 转换为 minor-unit `Long`；零值、溢出、错误千分位和三位小数不作为候选 |
| 必填字段 | 长截图缺日期、商户或金额的项目跳过；跳过数显示在识别批次名称中 |
| 提交 | 预览前不写账；提交按批次原子执行，失败不留下半批数据，成功后可整批撤销 |

## 4. 工程验收

- Desktop Kotlin：216/216，Android host：63/63，API 36 instrumentation：5/5。
- API 36 长图用例使用 1000×9000 PNG 强制走 5 个分片；顶部 `Coffee Shop / 35.50` 与底部 `Taxi Ride / 28.00` 均被设备内 OCR 识别。
- Android lint：0 fatal/error、14 warning；Debug、未签名 R8 Release、AndroidTest APK 构建通过。
- Debug/Release 权限实查不含网络、短信和图库读取能力；两包均通过 16 KiB 对齐检查。
- 解析回归覆盖多日期、多笔、重复候选稳定 ID、CSV 引号/逗号、汇总行跳过、无日期拒绝、零金额、三位小数、相邻商户和 200 笔上限。
- 全量质量门禁和财务应用校验器为 0 error/0 warning；当前未发现由本功能引入的 Critical/High/Medium 未关闭问题。

## 5. 仍需外部验证

- 代表性 Android 实体机的超长截图速度、内存、温升、低存储和系统文件提供方兼容性。
- 支付宝、微信、银行等不同版本真实界面在脱敏样本上的识别率；任何适配都必须保持保守解析和人工确认，不能变成私有 API 或自动抓取。
- TalkBack、硬件键盘、锁屏/强停/重启、卸载/恢复和生产签名/商店流程。
- Windows 本机 OCR，以及全部 Apple 平台实现与验收。
